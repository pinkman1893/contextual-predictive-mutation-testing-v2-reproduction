# 数据与模型来源

本仓库使用作者最终 v2 实验材料：[Zenodo 10654933](https://zenodo.org/records/10654933)。
其 README 链接的 [Google Drive 实验包](https://drive.google.com/file/d/1j6cuNaGKZmvNsbB1A489K0PG6pLj8svY/view)
是 63,775,365,120 字节的未压缩 TAR。

## 固定材料

`provenance/artifact_files.json` 记录 6 个原始测试分片、1024-token 保存预测与预处理源码的
原包路径、数据偏移、长度及 SHA-256。`provenance/checkpoint_index.json` 记录原始检查点 ZIP
目录、各模型张量的 CRC32、模型对象 pickle SHA-256，以及已检查的全局类型列表。
`provenance/tokenizer_manifest.json` 记录 CodeBERT 分词文件的官方来源与 SHA-256。

`prepare_assets.py` 只获取这些材料。预处理源码下载到 `author_v2/`，外部数据下载到
`artifact_v2/`，分词器到 `tokenizer/`，推理检查点到 `models/`；这些目录均被 Git 忽略。
不需要作者训练代码：模型反序列化时将其外层模型类映射为本地的 nn.Module 状态容器。

## 校验与兼容

原模型检查点约 1.49 GB，包含优化器状态。准备脚本只提取 203 个模型张量记录，
约 500 MB，每项校验原 ZIP CRC32；同时验证模型对象 pickle 的 SHA-256。
不会执行原训练优化器代码。加载推理检查点时验证容器 SHA-256 和批准的类型列表。

首次实验的推理检查点 SHA-256：

```text
55c5e0ad1fc2f1b3fdf72b304905ccb7423b38dae3be8d8fcfed03a62ecdb312
```

公开准备脚本使用确定的 ZIP 时间戳，重新封装后的容器哈希可能不同；它会生成本次检查点
manifest。原模型 pickle、张量及其校验值不变。`provenance/checkpoint_manifest.json`
保存首次实验记录，`models/v2_suite_checkpoint_manifest.json` 保存本地当前容器记录。

数据分片保留完整覆盖测试，1024-token 预处理只截断超长输入。
`provenance/input_manifest.json` 是首次编码的记录；新编码记录位于
`work/v2_generated_input/manifest.json`。原始数据和预处理源码固定，pickle 文件的字节哈希
也会受 Python 序列化实现影响。全量输入计数、长度、标签和来源均在推理前检查。

## 保存结果与参考结果

`test_pair_predictions.csv`、`test_suite_predictions.csv` 为本机新推理产生的结果。
`author_reference_*_predictions.csv` 从作者保存预测中提取，仅作为核验参考，包含标签、索引及概率，
不包含原始 Java 源码。`author_alignment.json` 记录不使用概率的分片标签对齐。

`verify_v2.py --results-only` 对公开 CSV/JSON 独立计数核验，不会下载模型、运行模型或重查
未下载的资产哈希。默认完整核验还检查本地输入、原数据和模型文件哈希。
